# 🧠 Epistemic DAG Architecture: Agent Crew & System Structure

## 1. System Overview
This system is a **Dynamic Directed Acyclic Graph (DAG) Engine**. It abandons traditional, token-heavy ReAct loops in favor of a "Macro-to-Micro Unroller." 

**The Core Philosophy:**
* Do not force one LLM to do two distinct cognitive tasks.
* Cure attention dilution by slicing tasks down to atomic levels before computation.
* Embed an **Epistemic Escape Hatch** at the base model level, forcing the system to physically halt and request missing data rather than hallucinating an autoregressive guess.
* Deploy via a single LLM Base Model with hot-swappable QDoRA adapters via vLLM to maximize hardware efficiency.

---

## 2. The Agent Crew (The LoRA Adapters)

### 👑 The Python Orchestrator (The DAG Engine)
* **Type:** Standard Python / NetworkX / vLLM Router (Non-LLM)
* **Role:** The heartbeat of the system. It maintains the task queue, manages state, and handles the hot-swapping of LoRA adapters. 
* **Relationship:** It is the boss. It receives outputs from the agents, updates the dependency graph, and triggers the Epistemic Error protocol if an agent halts.

### 🚦 Agent 0: The Metacognitive Router
* **Role:** The Triage Level. Reads the raw user input and categorizes the cognitive load.
* **Logic:** * If the input is a single, clear task -> Route to **Compute**.
  * If the input is long, explicit, and multi-step -> Route to **Decomposer**.
  * If the input is short, abstract, and requires high reasoning -> Route to **Expander**.
* **Epistemic State:** Low. Its only job is topological classification.

### 🔪 Agent 1A: The Decomposer (Semantic Slicer)
* **Role:** Context Window Protector. 
* **Logic:** Acts as a "dumb meat-cleaver." It takes massive, explicit workflows (e.g., standard operating procedures) and chronologically slices them into an array of isolated, atomic tasks.
* **Epistemic State:** None. It assumes the text it is slicing is valid. It exists purely to prevent the Compute nodes from suffering attention dilution.
* **Output:** An array of string-based atomic instructions.

### 🗺️ Agent 1B: The Expander (Sub-DAG Generator)
* **Role:** The Reasoning Unroller. 
* **Logic:** Takes highly abstract commands (e.g., "Deploy a secure server") and maps out the hidden knowledge gaps. It translates implicit reasoning into an explicit, strictly ordered sub-graph of atomic tasks with injected `dependencies` mapped to `task_ids`.
* **Epistemic State:** **High**. If it lacks the fundamental context to architect a plan, it trips the Epistemic Hatch (`has_sufficient_context: False`), lists the missing variables, and halts.
* **Output:** A structured array of `SubTaskNode` objects.

### ⚙️ Agent 2: The Compute Node (Atomic Executor)
* **Role:** The Specialist. 
* **Logic:** Receives one single, explicit, atomic instruction at a time. It executes the functional logic, math, or text generation required.
* **Epistemic State:** **Maximum**. Before executing, its `scratchpad` verifies that all required variables from the parent DAG exist. If data is missing (e.g., the Decomposer fed it a broken sequence), it trips the Epistemic Hatch, returning `missing_variables` and halting the specific node.

## 3. The Execution Flow

1. **Ingest:** User submits a prompt. Orchestrator attaches the **Router LoRA**.
2. **Triage:** Router classifies as `Type: Expand`. 
3. **Graph Generation:** Orchestrator swaps to **Expander LoRA**. Expander generates a 5-step sub-DAG with dependencies.
4. **Queueing:** Orchestrator parses the JSON and loads the 5 tasks into the DAG queue.
5. **Execution:** Orchestrator swaps to **Compute LoRA**.
   * It runs Task 1. (Success).
   * It runs Task 2. (Success).
   * It runs Task 3. **Epistemic Halt Triggered.** (Missing variable: API_KEY).
6. **Failsafe:** Orchestrator pauses the DAG, saves the state, and bubbles the missing variable request back to the user. State corruption is prevented.

### 2. Base Code for your Text Editor (`src/data_pipeline/schemas.py`)

Here is the foundational Pydantic mold code for your agents, implementing the exact "Upside-Down" Epistemic Hatches we designed. You can copy this directly into your IDE.

```python
from pydantic import BaseModel, Field

# ==========================================
# 1. THE DECOMPOSER (The Dumb Cleaver)
# ==========================================
class DecomposerDecision(BaseModel):
    # Pure semantic slicing. No epistemic hatch required here to save context.
    analysis_scratchpad: str = Field(
        description="Trace the workflow from start to finish. Identify the distinct chronological steps."
    )
    extracted_tasks: list[str] = Field(
        description="A chronological list of the atomic tasks. Each item MUST be a verbatim substring from the input text."
    )

# ==========================================
# 2. THE EXPANDER (The Sub-DAG Architect)
# ==========================================
class SubTaskNode(BaseModel):
    task_id: str = Field(description="A unique identifier for this sub-task (e.g., 'sub_1').")
    instruction: str = Field(description="The explicit, atomic instruction for the Compute node.")
    dependencies: list[str] = Field(description="List of task_ids that MUST be completed before this task. Empty [] if root.")

class ExpanderDecision(BaseModel):
    knowledge_gap_scratchpad: str = Field(
        description="Analyze the abstract task. Map out the logical chain of dependencies. What unstated steps are required?"
    )
    # Payload
    generated_sub_graph: list[SubTaskNode] = Field(
        description="The sequence of interdependent atomic tasks required to solve the abstract query. Output [] if missing core context."
    )
    # Escape Hatch
    missing_fundamental_context: list[str] = Field(
        description="List exactly what core parameters are missing that prevent planning. Output [] if sub-graph can be generated."
    )
    # Epistemic Classifier
    has_sufficient_context: bool = Field(
        description="MUST be True if generated_sub_graph has items. MUST be False if missing_fundamental_context has items."
    )

# ==========================================
# 3. THE COMPUTE NODE (The Atomic Executor)
# ==========================================
class ComputeDecision(BaseModel):
    analysis_scratchpad: str = Field(
        description="Analyze the atomic instruction against the available DAG context. Are all required variables present?"
    )
    # Payload
    execution_payload: str = Field(
        description="The final computed output or executed response. Empty string '' if data is missing."
    )
    # Escape Hatch
    missing_variables: list[str] = Field(
        description="List of required variables that are missing, preventing execution. Empty list [] if solvable."
    )
    # Epistemic Classifier
    has_sufficient_data: bool = Field(
        description="MUST be True if execution_payload has text. MUST be False if missing_variables has items."
    )

# ==========================================
# 4. THE ROUTER (The Triage Node)
# ==========================================
class RouterDecision(BaseModel):
    reasoning: str = Field(
        description="Analyze the length and implicit/explicit nature of the input to determine the required agent."
    )
    route_to: str = Field(
        description="MUST be one of: 'COMPUTE' (atomic), 'DECOMPOSER' (explicit multi-step), or 'EXPANDER' (abstract/implicit)."
    )
